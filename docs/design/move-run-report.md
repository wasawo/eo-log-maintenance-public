# 保存済み移動記録の実行別概要

更新日: 2026-10-28。[移動記録v1](move-record-v1.md)を利用し、[実装計画](../development/implementation-workflow.md)T1/T4の最小結果表示へつなぐ。

## 起動方法と今回の範囲

[Show-MoveRun.ps1](../../scripts/Show-MoveRun.ps1)で、指定した実行ID・PC・経路の記録を読む。PowerShell 7.6.7と、runtime依存を導入したPythonが必要である。次はダミー値の例で、実運用パスやIDを公開文書に転記しない。

```powershell
pwsh -NoProfile -File scripts/Show-MoveRun.ps1 `
  -JournalRoot '<非公開の移動記録root>' `
  -RunId '11111111-1111-4111-8111-111111111111' `
  -MachineId PC-A -Operation Sync
```

`-Operation Archive`はPC-Aだけに限定する。`-PythonExecutable`でPythonの実行ファイルを指定できる。既定の子プロセス待機上限は30秒、`-TimeoutSeconds`は1〜300秒。日本語の概要を表示し、`-AsJson`なら同じ項目をJSONで返す。journalの生成・更新・削除、元/保存先の読取や移動、Drive接続、回復処理は行わない。

指定するrootのOS権限とPCの設定資格は呼出し側で確認する。PC/経路の引数は読取範囲を選ぶもので、rootや実データへの操作権限を付与しない。正式な`SyncLogs.ps1`/`ArchiveLogs.ps1`は引き続き未提供であり、このコマンドの存在で配布可能にはしない。

## 集計の意味

[MoveRunReport.py](../../Common/MoveRunReport.py)がjournal全体の参照検査を済ませてから、指定PC・経路の記録をmove単位にまとめる。Python側の集計は既存のreport builderと同じく記録の派生表示であり、PowerShellが担当する実移動の制御・判断を置き換えない。

| 出力 | 数えるもの |
| --- | --- |
| 準備済み元 | 指定runにpreparedがあるmoveの数。fresh inventoryの全対象数ではない |
| 今回初めて完了 | 指定runの確定した完了記録のうち、過去runに同じmoveの完了がない数 |
| 削除確認 / 照合確認 | 今回初めて完了した元を、その記録の完了根拠で分けた数 |
| 完了済みの再確認 | 過去に完了済みで、指定runでも完了を確認したmoveの数。新規完了へ足さない |
| 未解決 | 今回の未完了/不明と、今回の記録がない過去の未解決move |
| 過去実行から | 未解決のうち、指定runの記録がなく持ち越した数 |

削除結果が照合記録から明示参照されていれば、同じrunでも参照後の照合を使う。明示的な先後関係がない複数の結果は時刻やファイル順で選ばず、不明として記録確認を案内する。過去の結果でも、別の記録に参照されていない末端が未解決なら持ち越す。

同じmove IDが異なる元を示せば不整合として未解決にする。逆に同じ型付き元参照・コピー内容へ複数のmove IDが割り当てられている場合は、二重計上を避けるため概要の生成自体を拒否する。retry時にmove IDを維持する正式coordinatorとの接続は、今後実装する。

指定runに記録がなければ、その旨を表示する。空journalや全て完了した過去記録があっても、「対象なし」「no_work」「実行成功」には変換しない。元の列挙やrun全体の受け入れを、この表示だけで認定しない。

終了コード0は概要の読取・表示ができたことだけを示す。未解決がある場合や指定runの記録がない場合も、その事実を正常に表示できれば0であり、移動処理の成功コードとして使わない。

## 表示と内部応答

概要にはrun ID、moveの不透明な対象参照、ログ種別、記録上の状態、次の対応を出す。未完了は移動処理の再実行、不明は現在状態の再観測、記録の対応不整合は記録確認を案内する。このコマンド自体はその操作を実行しない。

実パス、source/cloudの実体ID、ファイル名、本文、raw例外、Python stderrは表示しない。JSON出力も同じ限定項目だけとする。元/保存先の実体情報はprivate journalに保持し、詳しい元/保存先を示す非公開レポートの保存・表示は後続の作業である。

PowerShellは子プロセスをshell経由で起動せず、version・run/PC/routeの対応、未知key・型・固定値を検査する。異常応答は表示せず、読取失敗は許可した固定理由コードだけを返す。時間超過時は子プロセスツリーを停止し、成功へ置き換えない。この応答は内部の読取表示用で、Drive IPCの操作追加ではない。

記録を読めることは、現在の実体が同じ状態である証拠ではない。fresh inventory/run全体の状態、正式な再実行入口、実Drive、private詳細レポート、実運用件数での応答サイズ・性能、実環境受け入れは未完。T0/T1/T4全体を完了にしない。
