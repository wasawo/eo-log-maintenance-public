# 模擬実行全体の結果レポート

更新日: 2026-10-28。[模擬移動とjournalの接続](simulation-journal-integration.md)を拡張し、preparedより前の失敗も保存する。正式な実ログ・Drive実行の完成ではない。

## 保存と読戻し

`Invoke-EoLogMoveSimulation`の`ReportRoot`に、呼出し側が用意した専用ローカルフォルダを指定する。journalとは別の領域とし、同一・親子パスを拒否する。未指定なら保存しない。Dry Runはレポートも読書きしない。

モデル列挙と結果集計まで進んだ場合、`Common/SimulationRunReport.py`が`<run_id>.json`を非上書き公開し、同じbytesを読戻す。既存の原子的公開方式を再利用し、新しい依存は追加しない。同じ内容の再保存は許容し、別内容を上書きしない。JSONは最大8 MiBとし、未知key・重複key・不正な型/相対パス・理由と結果/次の対応の不一致を拒否する。

戻り値の`ReportSaveStatus`は`disabled`、`not_written`、`confirmed`、`unconfirmed`。保存確認できた概要を`RunReportSummary`へ返す。模擬実行の概要であり、実運用成功の証拠にはしない。

保存済みの概要だけを別プロセスで確認できる。

```powershell
python -B Common/SimulationRunReport.py --report-root <専用フォルダ> --read-run-id <runのUUID>
```

この読取は元/保存先を操作せず、ファイル名や相対パスをコンソールへ出さない。詳細はローカルのJSONを開いて確認する。日本語の詳細表示コマンドは未実装である。

## 個別結果と件数

レポートには次の内容を保存する。

- run・PC・経路、模擬実行であること、モデル列挙完了と列挙元件数。
- 元ごとの不透明な参照、ログ種別、rootからの相対パス、結果、理由、次の対応。
- 比較対象となる保存先候補の不透明な参照と相対パス。同名複数候補も列挙する。
- journalを読めたかどうかと、未解決のmove参照。

参照はモデルIDのSHA-256であり、実providerのidentityや匿名性の保証には使わない。絶対パス・設定・Drive ID・ログ本文・raw例外は記録しない。ただし相対パスやファイル名も非公開情報を含み得るため、詳細ファイルをGit・配布物・PRへ追加しない。private rootのACL・所有排他の資格確認は後続であり、指定だけで安全な領域とは認定しない。

コピー失敗・競合・不正名・保持期間内の除外も保存し、保存先確認済みのpreparedへ変換しない。照合も現在runの結果へ含めるため、個別結果件数が今回の列挙元件数を超える場合がある。削除結果確認と照合完了は別々に数える。

未解決の個別結果、journalの未解決、journal読取不能のいずれかがあれば、完了もある場合は部分失敗、なければ失敗とする。未解決がなく完了があれば成功、どちらもなければ対象なしとする。保持期間内の除外だけの実行は対象なしとなる。この判定は、列挙・処理が最後まで到達したモデルの範囲に限る。journal未指定なら過去の保存記録まで確認したことにはならない。

モデルとjournalの未解決件数は重複し得るため合算しない。過去の準備前失敗を次回まで自動持越しする履歴機構は追加せず、現在のモデル列挙と通常再実行で残りを扱う。

## 保存失敗と中断

レポート保存失敗は`ReportSaveStatus=unconfirmed`とし、`Status`や確認済み移動件数を書き換えない。元削除を取り消した、または移動が未実施だったとは報告しない。必要な移動記録の保存失敗による元保全とは別の扱いである。

強制終了・事前検証失敗・集計前の例外では最終レポートがない場合がある。ファイル不在だけで対象なしや成功とは判断しない。最終レポートから中断前のモデルを復元せず、削除や照合の認可にも使わない。古いレポートや一時ファイルの自動削除は行わない。
