# C-50 構造化条件入力モデル — 非規範的な提案

> 履歴/検討資料。承認済みの選択・未決候補・当時の監査根拠を含み、この移動は撤回/失効を意味しない。現在の基準は[正式要件](../../requirements/log-move-requirements.md)と[現行決定台帳](../../decisions/decision-register-c18-c32.md)。当時の対象/証拠を現在のruntime受け入れへ拡張しない。

**Status:** 保守者の決定のみを対象とした代替設計。この文書は、承認された C-50 マッピング/優先順位テーブルを修正するものではなく、実装を承認するものでもありません。

## 問題ステートメント

C-50 は、監視可能な 失敗 条件からスキーマ v1 error_code ホワイトリストまでの規範的な優先順位をすでに定義しています。リポジトリには、指定されたエラー コードを検証するファイナライザーとイベント ID 割り当てヘルパーが含まれるようになりましたが、実行可能な C-50 分類子はありません。信頼できる構造化入力の形状と検証ルールが明示的になるまで、分類子を安全に実装することはできません。

分類子は、カテゴリを推測するために、ローカライズされた/自由形式の例外メッセージ、例外クラス名、スタック トレース、生の OS テキスト、パス、または任意のメタデータを決して検査してはなりません。イベント ID を割り当てたり書き換えたりしてはなりません。既存の C-49 error_code 値のみを使用する必要があります。

## 候補モデル

| オプション | 入力形状 | 利点 | リスク/制限事項 |
| --- | --- | --- | --- |
| A — 呼び出し側が選択した条件 | 1 つの必須条件識別子。イベントプロデューサーによってすでに選択されています。 | 小さい API;検証が簡単。最小限の DTO。 | 各プロデューサーは完全な C-50 優先順位テーブルを個別に適用する必要があります。重複する観測は、呼び出しサイトごとに異なる方法で分類できます。中央の優先順位は強制されません。 |
| B — 観察された条件セット (**推奨**) | 信頼できるプロデューサーが確実に観察した、空ではない、または個別の正確な条件識別子の空の配列。分類子は、最も優先度の高い一致する C-50 行を一元的に選択します。空の配列は unknown_error にマップされます。不明な識別子または重複した識別子は入力を拒否します。 | 優先順位を一元化します。簡単なテーブル駆動テスト。自由形式の値はありません。呼び出し側の優先順位ロジックなしで複数の同時観測をサポートします。 | 正しさは依然として、構造化された証拠によって裏付けられた条件のみを主張するプロデューサーに依存しています。条件固有の前提条件は規範的であり、テストされている必要があります。 |
| C — 型付き観測オブジェクト | 明示的な成果物の種類/読み取り結果/検証結果、突然変異の観察、ファイル名の結果、アクセス拒否信号、操作の種類/結果、および C-50 に必要なその他の事実を含む、バージョン管理された内部オブジェクト。分類器はフィールド間の一貫性を検証し、観察された条件自体を導き出します。 | 最強のフィールドレベル検証。矛盾する証拠を拒否し、前提条件を一元的に強制できます。 | 最大の契約面とテスト面。現在のランタイム エントリ ポイントが設定できないフィールドを定義するリスクがあります。 null 可能性、許可される値、およびフィールド間不変条件を個別に検討する必要があります。 |

## オプション B: 候補条件の識別子と前提条件

次の識別子は **提案** であり、承認されていません。各トークンは、信頼できる構造化状態によって確実に確立された条件を表します。これは error_code ではないため、永続化された診断フィールドにはなりません。

| C-50 優先度 | 提案された条件識別子 | プロデューサーがそれを含める前に必要な証拠 | 結果のerror_code |
| ---: | --- | --- | --- |
| 1 | manifest_contract_invalid | マニフェストは正常に読み取られました。構文/スキーマ/同一性/整合性チェックに失敗しました。 | manifest_invalid |
| 2 | run_input_evidence_invalid | 実行入力証拠は正常に読み取られました。スキーマ/同一性/インベントリ/カウント/整合性チェックに失敗しました。 | evidence_invalid |
| 3 | observed_source_mutation | 承認された ID またはメタデータの前後の比較で不一致が観察されました。 | source_mutation_detected |
| 4 | target_filename_invalid | 分類中に厳密なファイル名/日付/期間/対象条件の検証が失敗しました。 | invalid_filename |
| 5 | structured_access_denied | Platform/API は、失敗した操作に対して明示的な構造化されたアクセス拒否シグナルを提供します。 | file_access_denied |
| 6 | directory_enumeration_failed | より具体的なアクセス拒否または変更条件を除いて、ソース ルート/到達ディレクトリの列挙に失敗しました。 | enumeration_failed |
| 7 | target_metadata_failed | 必要なタイプ/サイズ/タイムスタンプのメタデータを取得または検証できませんでした。 | file_metadata_failed |
| 8 | target_content_read_failed | ハッシュが完了する前にターゲット バイトを読み取ることができませんでした。 | file_read_failed |
| 9 | content_digest_failed | 意図したバイトは利用可能でしたが、ダイジェストの計算に失敗しました。 | hash_failed |
| 10 | general_contract_validation_failed | 明示的な検証の失敗は、上記のマニフェスト/証拠固有の条件ではカバーされません。 | validation_failed |
| 11 | report_serialization_failed | 検証されたレポート/証拠オブジェクトのシリアル化に失敗しました。 | serialization_failed |
| 12 | aggregation_failed | 入力を検証した後、要約/カウント/調整の導出に失敗しました。 | aggregation_failed |
| 13 | report_publication_failed | 集計/シリアル化が成功した後、最終レポート 失敗した を作成/公開します。 | publication_failed |
| 14 | *(認識される状態なし)* | 失敗イベントは存在しますが、提案/承認された条件が一致しません。 | unknown_error |

オプション B では、複数の個別の有効な条件識別子が指定された場合、分類子は数値優先度の最も低い行から error_code を返します。前提条件が満たされていない条件を指定してはなりません。 不明 条件トークン、重複トークン、間違った入力タイプ、または不正な形式の条件コレクションは無効な分類子入力であるため、修正された非開示エラーで拒否する必要があります。暗黙的に unknown_error にマップすることはできません。

## 任意のオプションの共有制約

1. 入力はイベント プロデューサーからの信頼された構造化状態であり、例外テキストから解析されることはありません。
2. マッピングは決定的であり、既存の C-50 優先順位を使用します。新しい error_code、フェーズ、または操作の値は導入されません。
3. 分類は、基礎となるイベントが最初に作成されたときに 1 回発生します。後のラッパーは error_id、error_code、フェーズ、および操作を保持します。同じイベントを再分類することはありません。
4. unknown_error は、実際に観察された 失敗 が既知の条件と一致しないことを意味します。計測の欠落、不正な分類子の入力、または既知のマッピングの欠陥を隠してはなりません。
5. 分類子 失敗 は、元のイベントをサイレントに破棄してはなりません。必要な診断フィールドを安全に入力できない場合、呼び出し元は証拠の最終処理に失敗する必要があります。
6. 単体テストでは、各 C-50 行、すべての優先順位の重複、アクセス拒否と汎用 I/O、読み取り可能と無効のマニフェスト/読み取り不能のマニフェスト/証拠、読み取りとハッシュ 失敗、コンテンツ処理前の無効なファイル名、不明 フォールバック、不正な入力の拒否、確定的な出力、および例外テキスト/クラス名が影響を与えないことの証明をカバーする必要があります。分類。

## 決定が要求されました

構造化入力モデルとして **A、B、または C** を選択します。 B または C が選択された場合は、規範的なレコードまたは実行可能な分類子コードが変更される前に、正確なフィールド/トークン名と無効な入力動作を承認します。推奨事項は **B** です。これは、ランタイム エントリ ポイントが存在する前に大規模なファクト DTO を導入せずに、すでに承認された優先順位テーブルを一元化するためです。これはまだ提案です。選択の余地はありません。

## 証拠と安全境界

現在のヘルパー/スキーマ テストは、ランタイム C-50 分類の証拠を構成しません。 scripts/SyncLogs.ps1 は引き続き監視員であり、scripts/ArchiveLogs.ps1 は不在です。 P0-008、P0-010、および P0-012 は開いたままになります。実際のログ、認証情報、運用パス、Google Drive 操作、アーカイブの有効化、または削除動作は対象外です。
