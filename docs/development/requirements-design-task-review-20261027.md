## 3. 現在地と乖離の確認

### 確認した事実

- PR #46までmainへ統合済み。直近の13実装コミットはsource/公開/ownerの資源制限、比較効率化、失敗・中断保全、schema外部取得禁止、隔離fixture接続が中心。
- `scripts/`の追跡ファイルはREADMEのみ。正式なSync/Archive入口、実Drive adapter、正式な永続writerは未実装。

### rootの診断・提案（未合意）

- 小さな補助処理の追加を「次の作業」として連続選択し、利用者の一連の操作が完成へ近づいたかを判断する区切りが弱かった。
- 安全要件は維持しつつ、タスクを利用シナリオと完成条件へ結び付ける。各詳細対策は、そのシナリオで防ぐ具体的な失敗・実装順の依存関係を説明できるものとして整理する。
- 既存安全ゲートを一律に不要扱いしたり、逆に全てを同じ優先度の着手前提へ並べたりしない。必要性・時期は利用者との確認後に決める。

## 5. 実装再開時に参照する形（提案）

各実装タスクに、少なくとも次を記載する。

1. 対応する利用シナリオと利用者に見える結果。
2. 根拠となる合意・既存要件ID・設計節。
3. 変更する入口/構成要素と、再利用する既存実装。
4. 完了を判定する一連の試験と、未実証の範囲。
5. 先に必要な判断・依存タスク、およびこのタスクで扱わない範囲。

この形式とタスクの内容自体も今回の対話で確認する。helper検査や試験件数だけを機能完成の判定にしない。
