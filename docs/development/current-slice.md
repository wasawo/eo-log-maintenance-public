# Current Slice — S3 Google Driveアダプタの隔離結合検証

現在の作業範囲の正本。利用者の明示指示でS2からS3へ切り替える。S1/S2の合成E2E完了と正式ACの部分検証を維持し、承認済み要件を変更しない。

## ゴール
S1 SyncとS2 Archiveの正式入口・期間選択・競合/元保持を再利用し、公式Drive v3 SDKの列挙・内容取得・非上書きupload・SHA-256照合を隔離環境で結合する。API応答模擬の成功と実Driveへの接続成功を区別する。

## 今回実装・検証する範囲
- 既存metadata/list/content readerを再利用し、不足するuploadと呼出しの接続だけを追加する。
- 正式Sync/Archive入口から、明示的なAPI模擬モードで公式SDKへ接続する。実サービスは明示的に注入するライブラリ境界とし、認証情報の自動探索・保存・refresh・既定認証・実接続CLIは追加しない。
- 合成file・固定の隔離rootと模擬HTTPのみを用い、列挙、copy/hash、同内容再利用、異内容/複数候補の保留、認証拒否、APIエラー、版変化、結果不明時の元保持を確認する。PythonのSDK内再試行は0とし、不明時にuploadを自動再送しない。
- Dry Runは意図的な書込・download・認証副作用を行わない。元削除と実Driveへの操作は提供しない。

## S3完了条件と未検証の扱い
1. S1/S2合成E2E回帰が成功し、正式入口から公式SDKと模擬HTTPによるupload/内容取得/照合の一連経路を確認できる。
2. 秘密非表示、PC-Bのarchive拒否、非上書き/競合保留、API失敗や内容/版不一致時の元保全を確認する。
3. 認証service/Windows保護store・同一Google principal・drive.file可視性/所有権/容量・対象rootなどの実環境資格を、別途承認された限定計画で確認する。
4. 利用者の明示承認を得た隔離実Drive test領域で、実APIの列挙・upload/download・内容照合とエラー時の保留を検証する。

1/2だけの成功はAPI模擬結合の部分達成。3/4が未承認・未実行ならS3未完とし、実Drive接続成功・正式AC合格・運用可能とは報告しない。実認証情報や隔離環境の有無は勝手に探索しない。

③④の準備・実行前ゲート・限定操作・停止/保持/後処理は[実Drive結合試験の限定計画](../design/drive-metadata-reader.md#s3-実drive結合試験の限定計画未承認未実施)を参照する。計画の文書化は実接続や認証情報操作の許可ではなく、認証/store/service/実試験runnerの未完も残る。

## 安全・権限境界
実ログ/本番Driveアクセス、元/クラウド元削除、認証情報/実ID/実pathの公開、Q5/役割/安全仕様の変更、S4への移行は禁止。隔離実Drive領域も別途の明示承認を得るまで操作しない。正式AC/P0状態を根拠なく変更しない。実Drive操作の必要が残った段階では、根拠・限定計画・未承認範囲を示して利用者の判断を待つ。

## 作業上限
今回の承認済み実装・模擬結合・必要文書はPR作成と標準条件成立時のsquashマージまで許可済み。PR3件または30分、S3完了、承認待ちの判断事項発生のいずれかで停止する。S4へ進まない。
