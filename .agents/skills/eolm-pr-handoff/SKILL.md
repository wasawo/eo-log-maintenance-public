# Git・PR・引き継ぎ

rootが担当する。現在の利用者指示と [AGENTS.md](../../../AGENTS.md) を確認し、依頼に含まれる段階だけを実施する。既存PR許可・CI代替・過去の自動継続を別操作へ拡張しない。

## コミット・PR

- `git status --short --branch`、`git branch -vv`、`git remote -v` と必要な実GitHub状態を照合する。未コミット/ステージ済み変更を保全し、利用者が含めるよう指定した変更も確認する。
- 差分とステージ内容を確認する。実値・秘密・runtime証拠・禁止配布物を含めず、作成者メールは既存GitHub noreply設定を確認する。
- 関連仕様・コード・テスト・handoffは同じPRにまとめ、要件ID/P0への影響と受け入れ限界を示す。PR本文には問題、変更後の動作、検証、残課題を書く。
- 検証が必要なら [eolm-validation](../eolm-validation/SKILL.md) を読む。PR作成依頼だけではマージしない。外部操作は依頼で認可された範囲に限る。

## CI・マージ

- 利用可能なら最新PR HEADのValidateとPackage Validationを確認する。追加コミット後に古いSHAの成功を流用しない。
- CI待ちは初回確認後、90秒間隔で最大5回再確認する。未完/失敗なら状態・URLを報告しマージしない。長い待機は分割して途中の利用者指示を受け取れるようにする。
- CI不可なら理由、ローカル検証範囲、環境差、未実行CIを明記する。代替をCI成功と記載せず、マージ条件を勝手に緩和しない。特定PRの代替承認は他PRに適用しない。
- マージが承認済みでも最新HEADの必要検査と実マージ要件を確認する。マージ後は実SHAとmainのCIを確認する。

## 引き継ぎ

- 各作業単位で [next-chat.md](../../../docs/handoff/next-chat.md) をrootが更新する。更新日、確認した基準SHA、ブランチ/PR、変更、検証結果とURL、未完了・判断待ち、次の具体作業、未実証範囲を記録する。
- 最新状態は上部へ置く。未コミット・未push・未マージ・未実行を区別し、将来の成功を先に書かない。承認/中断状態も保持する。
- 恒久規則・モデル設定をhandoffへ複製しない。長い過去記録は `docs/handoff/archive/` へ保存し、旧指示を現行指示として実行しない。
